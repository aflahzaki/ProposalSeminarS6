# Proposal V8 generation script for preprocessing methodology update

A Python script (`create_proposal_v8.py`) that loads the V7 proposal `.docx` and performs 11 targeted text replacements to produce V8. The edits align the proposal narrative with Al Bataineh et al. (2026) Algorithm 3: MICE becomes Median Imputation, Standardization becomes MinMax Scaling, the preprocessing order changes from split-before-scale to scale-before-split, and the Canada Water Quality Dataset is introduced as an external validation reference. The script includes a self-verification step that reloads the output and checks all 11 changes passed.

**Watch for:** The inserted Canada dataset paragraph (Para 211) lacks explicit font formatting and will render at the document's Normal style default (~11pt) rather than the 12pt Times New Roman used by all neighboring paragraphs (confirmed). The `set_paragraph_text` helper preserves paragraph-level rPr (which carries font defaults for existing paragraphs), but `insert_paragraph_after` only sets a style reference without copying the rPr block — creating a visual inconsistency in the output document.

## High-level view

The script operates as a straightforward find-and-replace pipeline: load document, overwrite specific paragraph indices with new text, insert one new paragraph, save. The approach relies entirely on hard-coded paragraph indices from V7 (276 paragraphs), which means the script is single-use by design and will silently corrupt the document if V7's paragraph count ever changes.

The formatting strategy preserves paragraph properties (pPr) when rewriting existing paragraphs, which correctly inherits the Times New Roman 12pt from the paragraph-level rPr. However, the newly inserted Canada paragraph is constructed from raw OxmlElement without copying the rPr block from its sibling, so it will display at the wrong font size in Word.

The edit ordering is deliberate: the paragraph insertion (Edit 7) is performed last because it shifts all subsequent indices by +1. The verification step correctly accounts for this shift when checking post-insertion indices.

## Font inheritance gap on the inserted paragraph

The `insert_paragraph_after` function builds a new `w:p` element from scratch. It sets `w:pStyle val="Normal"` but does not copy the `rPr` from the sibling paragraph's pPr. The "Normal" style in this document defines font size 22 half-points (11pt) with no font family override, so the Canada paragraph at index 211 will render at 11pt in whatever Word's theme font is, rather than 12pt Times New Roman.

The fix is to copy the pPr's rPr from `paragraphs[210]` into the new paragraph's pPr element before inserting it, or to set explicit run properties on the new run.

## Formula downgrade from oMath to plain text

V7's Para 223 contains an `m:oMathPara` element — a proper Word equation object that renders with the Cambria Math font and proper fraction layout. The script's `create_minmax_formula_paragraph` replaces this with an italic text run containing `x' = (x - x_min) / (x_max - x_min)`. This will display inline as regular text, visually inconsistent with any other equations in the document that remain as oMath objects.
