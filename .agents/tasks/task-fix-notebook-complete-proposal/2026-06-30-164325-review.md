# NaN guard for SMOTE-ENN pipeline and Gantt/reference additions to proposal V8

This change fixes a `ValueError: Input y contains NaN` crash in the Canada Water Quality notebook's hyperparameter tuning cell by adding three layers of NaN detection and removal: immediately after SMOTE-ENN resampling, at the end of the SMOTE decision logic, and defensively at the start of the grid search cell. A separate script (`fix_proposal_v8.py`) modifies the V8 proposal docx to fill a Gantt chart with blue cell shading and insert three reference placeholders in BAB III.

**Watch for:** The Gantt shading appends a duplicate `w:shd` element instead of replacing the existing one (confirmed). The `smote_success = False` assignment inside the NaN cleanup block is dead code — training proceeds regardless and overwrites it (confirmed). No test or execution validates the notebook actually runs end-to-end after the fix.

## High-level view

The NaN fix uses a filter-and-drop approach at three checkpoints: post-SMOTE-ENN resampling, end of SMOTE decision logic, and start of grid search cell. The first catches NaN from the resampling algorithm, the second catches NaN in whichever branch was selected as `X_train_final`/`y_train_final`, and the third is a belt-and-suspenders guard before `StratifiedKFold.split()`.

The proposal modification script appends a new `w:shd` element to Gantt cells without removing the pre-existing one, creating duplicate shading elements. Word renders the last one (correct visually) but the XML is technically malformed per OOXML spec and may confuse LibreOffice or PDF converters.

## Dead `smote_success` flag in NaN cleanup

After the first NaN cleanup (line 27–35 of cell 10), if the cleanup removes more than 50% of rows or NaN persists, `smote_success` is set to `False`. However, execution continues unconditionally into the `try` block that trains `ngb_smote` on the partially-cleaned resampled data. If that training succeeds, `smote_success` is overwritten to `True` at line 55, nullifying the earlier flag. The intended semantics — "if SMOTE produced too much garbage, don't use it" — are not enforced. The comparison on line 82 (`use_smote = smote_success and (f1_smote > f1_no_smote)`) will still pick SMOTE if it scores higher, even when 50%+ of the synthetic samples were NaN.

To fix: wrap the training block in `if smote_success:` so that a degraded SMOTE output is never evaluated.

## Duplicate shading in docx XML

The `set_cell_shading` function in `fix_proposal_v8.py` appends a new `w:shd` child to `tcPr`:

```python
tcPr = tc.get_or_add_tcPr()
shading = OxmlElement('w:shd')
shading.set(qn('w:fill'), color)
...
tcPr.append(shading)
```

The Gantt cells already carry a `w:shd` with `fill="BFBFBF"` (gray background from the template). The result is two `w:shd` elements under the same `tcPr`. Microsoft Word renders the last one, so the visual output is correct. But the OOXML spec says `tcPr` should contain at most one `w:shd`. LibreOffice, Google Docs import, and PDF converters may render the first (gray) or throw a validation warning.

The fix:

```python
existing = tcPr.find(qn('w:shd'))
if existing is not None:
    tcPr.remove(existing)
tcPr.append(shading)
```

## Reference placeholder insertion fragility

The three placeholders (`[ref Mothilal2020]`, `[ref Canada-Figshare]`, `[ref Guo2017]`) are inserted via string replacement on hardcoded paragraph indices (211, 237, 247). Any edit to the document that adds or removes a paragraph will shift these indices and cause the script to target wrong paragraphs on re-run. The script does verify presence of target text before modifying (preventing silent corruption) and handles idempotency via `if ref not in text` guards.
