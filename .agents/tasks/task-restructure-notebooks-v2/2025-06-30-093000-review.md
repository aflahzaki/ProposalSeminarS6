# Notebook restructuring to match methodology diagram order

Both V2 notebooks (Kadiwal binary classification, Canada multi-class) were reorganized from a Tuning-first flow to the correct methodology diagram order: Training with fixed parameters, Baselines, Tuning, then comparative Evaluation. Two new named sections — "Analisis Kalibrasi" and "Prediksi Kualitas Air" — were extracted from what was previously inline visualization code into standalone pedagogical sections. The evaluasi section now compares pre-tuning vs post-tuning metrics side by side rather than reporting only tuned results.

Watch for: Variable dependency between `ngb_initial` (cell 12) and `results_initial` (cell 14) requires strict top-to-bottom execution — any out-of-order cell run will produce NameErrors (confirmed). The fixed NGBoost parameters are correct but `col_sample=0.8` is not in the tuning grid, creating an asymmetry in the before-vs-after comparison (confirmed).

## High-level view

The restructuring inserts two new code cells (Training NGBoost with fixed params, Training Baselines) before the existing tuning section. The fixed parameters (n_estimators=300, lr=0.05, minibatch_frac=0.8, col_sample=0.8, max_depth=4 for Kadiwal/Bernoulli; same with k_categorical(5) for Canada) are hardcoded per the methodology diagram. Both notebooks store `results_initial` in the baseline cell, which the evaluation cell later consumes for delta computation.

The evaluation section was rewritten to compute per-model deltas (Initial vs Tuned) across all metrics. For Kadiwal, ECE is added retroactively inside the evaluation cell via `calculate_ece()`. Canada's evaluation skips ECE at this stage — it appears later in the dedicated "Analisis Kalibrasi" section with a proper multi-class ECE function, making the Canada evaluation table less complete than Kadiwal's.

"Analisis Kalibrasi" consolidates calibration curves and uncertainty zone analysis (previously scattered across evaluation visualization cells). "Prediksi Kualitas Air" is entirely new — it demonstrates probabilistic predictions on representative test samples with confidence zones.

The tuning grid samples 20 of 192 combinations randomly for NGBoost (manual implementation due to sklearn incompatibility), then uses standard GridSearchCV for XGBoost and Random Forest. The tuned models are stored as `ngb`, `xgb`, `rf` — the same variable names downstream DiCE cells expect.

### Section ordering and the methodology diagram contract

The old ordering was: SMOTE-ENN → Tuning → Training (tuned) → Evaluasi. There was no baseline (pre-tuning) model to compare against. The new ordering inserts two cells between SMOTE-ENN and Tuning:

```
Old:  EDA → Preprocess → SMOTE → Tuning → Training (tuned) → Eval
New:  EDA → Preprocess → SMOTE → Training (fixed) → Baselines → Tuning → Training (tuned) → Eval (before vs after)
```

This matches the methodology diagram's flow and enables the comparative evaluation that was previously impossible.

### The col_sample parameter asymmetry

In both notebooks, the initial NGBoost model uses `col_sample=0.8` (hardcoded from the diagram). The tuning grid searches over `n_estimators`, `learning_rate`, `minibatch_frac`, and `max_depth` — but not `col_sample`. The tuned retraining in cell 18 also hardcodes `col_sample=0.8`. This means the before-and-after comparison is effectively comparing the same col_sample value, and the "improvement" delta only reflects changes in the other four parameters.

If the diagram specifies col_sample=0.8 as fixed, this is intentional but should be documented. If not, the tuning grid has a gap — the best model may benefit from a different col_sample that will never be explored.

### Variable flow and cell dependency chain

The critical data flow:

```
Cell 12: ngb_initial = NGBClassifier(...) → trains, produces y_pred_ngb_init, y_prob_ngb_init
Cell 14: initial_models = {'NGBoost': ngb_initial, 'XGBoost': xgb_initial, 'RF': rf_initial}
         results_initial[name] = {metrics...}  ← dict consumed later
Cell 16: Grid search → best_ngb_params, best_xgb_params, best_rf_params
Cell 18: ngb, xgb, rf = retrained with best params
Cell 20: results_tuned computed; comparison table prints results_initial vs results_tuned
```

The risk is Colab's non-linear execution model — a user jumping to cell 20 after a restart hits NameError on `results_initial`. The markdown for cell 19 ("Evaluasi Model - Perbandingan Sebelum vs Sesudah Tuning") doesn't mention this dependency.

### ECE computation asymmetry between notebooks

Kadiwal's evaluation cell (20) adds ECE to `results_initial` retroactively using `calculate_ece` defined in the same cell, so the comparison table includes ECE. Canada computes ECE later in the Analisis Kalibrasi section (cell 28) using a separate `calculate_ece_multiclass` function. The Canada evaluation cell (20) does not include ECE in its comparison table — ECE comparison only appears in the kalibrasi section. This means the Canada evaluation table is less complete than Kadiwal's at the point of initial comparison.
